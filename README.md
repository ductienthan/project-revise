# Preflight

Preflight stores your failures, turns them into a checklist for your next project, and blocks the project from starting until the required items are resolved. It has a command-line client, `preflight`, and a web dashboard served by the same FastAPI server.

All seven build phases in [the design](docs/design.md#17-build-phases) are built and tested. Deployment is not set up yet.

## Quick start

These steps run Preflight on your machine with SQLite. You need Python 3.12 and [uv](https://docs.astral.sh/uv/).

1. Install the dependencies and create the database.

   ```sh
   uv sync
   uv run alembic upgrade head
   ```

2. Create your account. The command asks for a password of at least 12 characters.

   ```sh
   uv run preflight-server create-user --username me
   ```

3. Start the server.

   ```sh
   uv run uvicorn preflight.server.asgi:app --reload
   ```

   The dashboard is now at http://127.0.0.1:8000.

4. In another terminal, sign in the CLI. It prints a code and opens the dashboard so you can confirm it.

   ```sh
   uv run preflight login
   ```

   The CLI prints `Signed in.` To sign in without a browser, run `uv run preflight login --password` instead. It asks for the password with hidden input and works only over HTTPS or localhost.

5. Create a project and start it.

   ```sh
   uv run preflight new my-project
   uv run preflight my-project start
   ```

   `start` lists what it would send to AI. Approve each item, answer the questions, and resolve the required checklist items. With no AI configured, it builds the checklist from your history and rules.

## Everyday commands

```sh
uv run preflight my-project add-link https://example.com/docs --capture
uv run preflight my-project fail "Retry loop hung"
uv run preflight my-project review          # review again after requirements, links, or history change
uv run preflight my-project close           # retrospective
uv run preflight drill                      # practice drills from past failures
uv run preflight report --week
uv run preflight import old-failures.csv    # backfill: project, title, date, and optional fields
```

[The CLI reference](docs/cli.md) has every command and option. `preflight <project> --help` shows the project actions.

## AI providers

With `PREFLIGHT_ANTHROPIC_API_KEY` set, reviews use Claude Opus 5.5 and the smaller tasks use Claude Haiku 5.5. `PREFLIGHT_AI_MONTHLY_BUDGET_USD` (default 5) refuses any call whose worst-case cost would pass the month's budget. Set a matching spend limit in the Anthropic Console as well.

Without a key, the server uses a local [Ollama](https://ollama.com) at `PREFLIGHT_OLLAMA_URL`. It picks the largest installed model unless `PREFLIGHT_OLLAMA_MODEL` is set, and splits long material to fit `PREFLIGHT_OLLAMA_CONTEXT_TOKENS`. Local calls cost nothing, and the material goes only to that Ollama server. Every item still needs your approval before it is sent. Set `PREFLIGHT_AI_PROVIDER` to `anthropic`, `ollama`, or `off` to choose. The default, `auto`, behaves as described.

Without either provider, everything except the AI review, AI suggestions, and AI drill grading still works. [The design](docs/design.md#7-ai-integration) explains the approval gate, and [the configuration reference](docs/configuration.md) lists every setting.

## Link capture

Link capture fetches public pages only. Each request connects to an address that was checked as public, so it cannot be turned against the server's own network. Pages that need JavaScript are skipped unless you set `PREFLIGHT_CAPTURE_BROWSER=true` and install the browser extra:

```sh
uv sync --extra browser
uv run playwright install chromium
```

Every request the browser makes passes the same public-address check. The browser does its own DNS lookups, though, so it cannot pin addresses the way plain capture does. Leave it off on an internet-facing server unless you need it.

## Check your changes

Run this before every commit. It takes about two minutes and stops at the first failure.

```sh
./scripts/check.sh
```

It runs these steps:

1. `ruff` on the source, tests, and scripts.
2. `scripts/check_review_migration.py`, which proves the data migration round trip on a throwaway database.
3. `scripts/validate_requirements.py`, which runs the test suite and `scripts/e2e.py` once and checks every requirement against them. [`validation/requirements.json`](validation/requirements.json) maps each requirement to the tests and end-to-end checks that prove it. The script fails when a requirement in the document has no entry, when an entry marked met has no evidence or cites a test that does not exist, or when any cited evidence fails. It writes [the validation report](validation/report.md).
4. `scripts/mutation_check.py`, which breaks 20 protections on purpose in a throwaway copy of the code, such as the start gate, the AI approval gate, CSRF, data separation between accounts, and the private-address guard. It confirms the tests catch every one.

When you add or change a requirement, update its entry in `validation/requirements.json`. When you add a protection, add a mutation for it. When you change a command, a setting, an endpoint, or a table, regenerate the references:

```sh
uv run python scripts/gen_docs.py
```

A test fails while any generated reference is out of date, and another fails when a link in these docs points at a missing file.

`scripts/e2e.py` runs the real migration, server, CLI binary, and dashboard forms. It points the server at local fakes of the Anthropic Messages API and of Ollama, so it needs no API key and spends nothing. The tests and `scripts/e2e.py` use SQLite by default. To run them against Postgres, set `PREFLIGHT_TEST_DATABASE_URL` or `PREFLIGHT_E2E_DATABASE_URL` to an empty database. The tests drop and recreate every table.

### Check the review prompt

`tests/golden/review_payload.txt` holds the exact review payload for a fixed project, so a prompt change shows up as a diff. After an intended change, regenerate it:

```sh
PREFLIGHT_UPDATE_GOLDEN=1 uv run pytest tests/test_golden.py
```

`scripts/eval_review.py` runs the real review on the cases in `evals/review_cases.json` against the configured provider. It scores how many relevant past failures the review addresses, how many unrelated ones it brings in, how many drafts it drops, and which question categories it covers. With Ollama it costs nothing:

```sh
PREFLIGHT_OLLAMA_MODEL=gemma4:12b uv run python scripts/eval_review.py --trials 3
```

## Run it on a server

In production, point `PREFLIGHT_DATABASE_URL` at Postgres and set `PREFLIGHT_REQUIRE_HTTPS=true`. [The design](docs/design.md#12-hosting-and-cost) compares hosts and costs.

Login lockout and rate limits are counted per client address. Behind a reverse proxy, such as on Render, every request arrives from the proxy's address unless uvicorn trusts the proxy's `X-Forwarded-For` header. Without that, one attacker can rate-limit every visitor. Start the server with:

```sh
uvicorn preflight.server.asgi:app --host 0.0.0.0 --port $PORT --proxy-headers --forwarded-allow-ips "<proxy address or range>"
```

Set `--forwarded-allow-ips` to your host's proxy addresses. Use `*` only if the service cannot be reached except through that proxy. Check your host's documentation for which applies.
